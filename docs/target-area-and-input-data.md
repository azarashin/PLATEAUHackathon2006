# 対象地域、表示モード、入力データ

Issue #2で、後続の都市モデル読込、日陰計算、道路グラフ、経路探索が共通して使う地域と入力条件を定めます。
調査結果は2026年8月23日時点です。外部データ本体はGitへ追加せず、取得元と再取得手順を文書で管理します。

### 課題検討地域

シミュレーション結果を準備する固定地域は、次の4自治体と市ヶ谷の計5地域です。各中心から半径4 km
（面積約50.3 km²）をデータ取得・解析範囲とします。デモ起終点は固定せず、利用者が地図UIから道路ネットワーク上の
地点を選択します。徒歩約1時間の移動を想定し、選択可能な経路長の目安を3〜5 kmとします。半径4 kmは直線距離による
解析範囲、3〜5 kmは道路ネットワーク上のデモ経路長であり、別の条件として検証します。

| ID | 自治体 | 自治体コード | 中心 | 座標（経度, 緯度） | シミュレーション |
|---|---|---|---|---|---|
| `kyoto` | 京都市 | `26100` | 京都駅 | `135.758770, 34.985350` | 半径4 kmで必須 |
| `maizuru` | 舞鶴市 | `26202` | 東舞鶴駅 | `135.3946946, 35.4685404` | 半径4 kmで必須 |
| `fujisawa` | 藤沢市 | `14205` | 藤沢駅 | `139.487293, 35.338882` | 半径4 kmで必須 |
| `saitama` | さいたま市 | `11100` | 大宮区天沼町二丁目 | `139.640025, 35.900757` | 半径4 kmで必須 |

京都の指定「京都市駅」は「京都駅」を指すものとして登録します。駅の座標は代表点であり、プラットフォームや出入口の
個別座標ではありません。さいたま市は町丁境界の図形中心点を中心座標とします。

さいたま市は海に面していないため、内水氾濫と道路冠水を環境コストの対象にします。天沼町二丁目には大雨・台風時の
道路冠水・浸水履歴が複数あり、住宅地、幹線道路、生活道路が混在します。従来案の約500 m×500 mは解析範囲にはせず、
半径4 kmの中で浸水コストを重点的に与えるシナリオ領域として扱います。UIで選んだ起終点について、通常最短経路が
重点領域を通過する場合に、冠水時には代替経路へ切り替わる様子を表示します。

### GPS現在地

MVPのGPSモードは現在位置へ地図中心を移動し、位置が固定5地域の解析範囲内なら既存結果を利用します。
固定範囲外では結果なしを許容します。

- 利用者が操作したときだけブラウザのGeolocation APIを呼び出す。
- HTTPS上で位置情報の利用許可を求める。
- 取得した緯度・経度と精度をサーバーへ送信せず、ブラウザ内の表示にだけ使う。
- 位置履歴を保存しない。
- 許可拒否、タイムアウト、位置取得不可を個別に案内する。
- 精度円を表示する。MVPでは測位精度の改善を完了条件にしない。
- シミュレーション範囲外でも地図移動は成功とし、結果なし状態を表示する。
- 近い課題検討地域の結果へ暗黙に置き換えない。

実用時は、現在位置を中心とする半径4 kmのコスト情報を定期的に取得し、その範囲内の道路エッジだけ
環境コストの重みへ更新します。現在位置の更新に合わせてコスト窓と道路重みを更新し、最適経路を再計算します。
範囲外の道路は基礎移動コストを維持し、環境コストが未取得であることを区別します。

```text
現在位置更新
  → 半径4 kmのコスト情報を取得
  → 対象エッジの環境コスト重みを差し替え
  → コスト版を更新
  → 古い経路計算を破棄
  → 現在位置から目標地点まで再探索
```

## シミュレーション結果の状態

地域選択とデータ読込を分離し、少なくとも次の状態をUIとデータ契約で区別します。

| 状態 | 意味 | UI |
|---|---|---|
| `available` | 選択位置に対応する結果がある | 道路コスト、経路、KPIを表示 |
| `not-precomputed` | 対象地域だが結果をまだ生成していない | 準備中または未生成と表示 |
| `outside-coverage` | GPS位置が固定5地域の計算範囲外 | 地図は表示し、結果がないことを案内 |
| `load-error` | 本来ある結果の取得に失敗 | 再試行可能なエラーとして表示 |

`outside-coverage`を通信エラーや空データとして扱いません。GPS位置に対応する結果がないことは、
仕様上許容された正常状態です。

### 地物の使い分け

- `bldg`: 建物による遮蔽。5地域すべてで必須。
- `tran`: 道路面の表示と位置照合。経路グラフの正本には直接使わない。
- `dem`: 地表高と建物配置。5地域すべてで必須。
- `veg`: 樹木による遮蔽。収録されている範囲だけで使用する。
- 歩行経路グラフ: OpenStreetMapの`highway`ネットワークから地域別に生成する。

舞鶴市と藤沢市の2025年版カタログには`veg`がありません。植生データがない場所を「樹木なし」とは判定せず、
建物のみの日陰と樹木を含む日陰の条件差をシナリオメタデータへ記録します。この条件差はMVPでは許容します。

## 座標とUnityへの変換

| 地域 | シミュレーション平面座標 |
|---|---|
| 京都市・舞鶴市 | JGD2011 / 平面直角座標系第VI系、EPSG:6674 |
| 藤沢市・さいたま市・市ヶ谷 | JGD2011 / 平面直角座標系第IX系、EPSG:6677 |

共通規則：

1. PLATEAU CityGMLはEPSG:6697として読む。
2. 地域に対応する平面直角座標系へdouble精度で投影する。
3. 各地域の境界中心をUnityローカル原点とする。
4. Unityでは`X=東方向`、`Y=上方向`、`Z=北方向`とし、原点差し引き後にfloatへ変換する。
5. ViewerのGeoJSONはRFC 7946に従い、OGC:CRS84の`[経度, 緯度]`を使う。
6. 高さはPLATEAUの東京湾平均海面基準の標高を使い、GPSの楕円体高と混在させない。

地域ごとに異なるUnity原点を持つため、ローカル座標だけで地域を識別しません。正式データには必ず`areaId`、
元のCRS、ローカル原点を含めます。

## 日時条件

- 回帰試験の代表日は`2025-08-01`とする。
- 時刻は各地域の現地時刻`08:00`から`17:00`まで、1時間間隔の10スライスとする。
- 5地域とも`Asia/Tokyo`、UTC+09:00、夏時間なしとする。
- 太陽位置計算は各地域の緯度・経度を使用し、1地域の結果を別地域へ流用しない。

```text
data/raw/
├── plateau/
│   ├── 26100-kyoto-2025/
│   ├── 26202-maizuru-2025/
│   ├── 14205-fujisawa-2025/
│   ├── 11100-saitama-2025/
│   └── 13101-ichigaya-2025/
└── osm/
    ├── kyoto/
    ├── maizuru/
    ├── fujisawa/
    ├── saitama/
    └── ichigaya/
```

データ本体は`.gitignore`の対象です。各ローカルディレクトリのmanifestへ`areaId`、取得日時、固定年度URL、
ファイルサイズ、SHA-256、対象円、OSM要素の抽出日時を記録します。Unity解析時間は許容しつつ、
CityGML検索APIで半径4 kmと交差するメッシュを抽出し、解析単位と再実行条件を固定します。

PLATEAUの利用条件は[PLATEAUサイトポリシー](https://www.mlit.go.jp/plateau/site-policy/)と、
ダウンロード物に同梱される利用条件を確認します。表示例は次のとおりです。

OpenStreetMapデータはODbL 1.0です。Viewerには次の帰属を常時表示し、`OpenStreetMap`から
`https://www.openstreetmap.org/copyright`へリンクします。

```text

```

地域ごとに自治体名、PLATEAU年度、OSM抽出日を結果メタデータへ含めます。

## 手動補正方針

- rawのCityGMLとOSM XMLは直接編集しない。
- 補正は`areaId`を持つ`data/road-network-overrides.geojson`へ差分として記録する。
- 補正には安定ID、対象OSM ID、操作種別、理由、根拠、作成日、確認者を持たせる。
- 補正後にID一意性、参照整合性、地域境界、起終点接続性を地域ごとに再検証する。
- OSMへ反映できる修正はOSMの編集方針に従い、プロジェクト固有の推測を投稿しない。

## MVPで許容する制約と後続対応

1. **5地域分の計算量**

   CityGML zipは合計約9.0 GB、固定解析範囲は1地域あたり約50.3 km²です。Unity解析時間の増加はMVPで許容します。
2. **UI選択する起終点の検証が未完了**

   起終点は固定せず地図UIで選択します。5地域それぞれで道路へのスナップ、到達不能地点の拒否、3〜5 kmの経路例、環境コストによる経路差を検証します。
3. **植生条件が地域間で不均一**

   舞鶴市と藤沢市には2025年版`veg`がありません。この条件差をメタデータへ記録し、MVPでは許容します。
4. **結果の組合せが増える**

   5地域×10時刻だけで50スライスです。`areaId`、対象円、時刻、コスト版をキャッシュキーに含めます。
5. **動的コスト更新の整合性**

   移動中の取得競合、古い経路の表示、4 km境界付近の重み切替、通信失敗時の継続動作はIssue #23で設計します。
6. **GPS精度とプライバシー**

   MVPでは端末精度の差を許容します。保存・送信を行わない方針を維持し、本番品質の権限・精度・監査はIssue #24で扱います。

植生モデル不足地域の補完と地域間比較条件はIssue #25で扱い、MVPをブロックしません。
市ヶ谷1地域分の一括解析を先に実施し、必要な場合のメッシュ分割解析はIssue #26で扱います。
