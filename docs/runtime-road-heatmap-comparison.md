# Runtime 道路別ヒートマップ比較

Runtime の「道路別ヒートマップ」タブは、施策前（都市パッケージに含まれる基準コスト）と、Runtime で再計算した施策シナリオの道路辺ごとの差を描画します。

## 操作

1. 施策シナリオを保存し、対象時刻の解析を実行する。
2. 「経路・KPI 比較」で開始・終了地点、案A（必要なら案B）、比較時刻を指定し、**同一条件で経路・KPIを比較**を実行する。
3. 「道路別ヒートマップ」で指標（日陰率、日射曝露時間、または環境コスト）と案A/案Bを選び、**道路別比較を実行**する。環境コストでは最短（係数0）、バランス（係数0.5）、日陰優先（係数2）の経路プロファイルを明示選択する。
4. 地図上の道路色と凡例を確認する。個別の物理道路辺は道路IDを入力して詳細を確認できる。

凡例では、改善=緑、悪化=オレンジ、変化なし=青灰、一部欠測（内部値: `partial`）=黄、比較不能（内部値: `missing`）=暗灰と表示します。日陰率は増加が改善、日射曝露時間と環境コストは減少が改善です。オレンジは注意を要する悪化、黄は一部欠測、暗灰は比較不能として区別します。

## 比較条件の固定

道路別比較は単独の任意データ比較ではありません。直前に完了した Runtime 経路・KPI 比較の次の条件と完全一致する場合だけ実行されます。

- 都市ID、比較時刻、道路ネットワーク topology fingerprint
- 都市パッケージ版と manifest fingerprint
- 経路・KPI比較の comparison fingerprint
- 比較済みの案A/案Bの Runtime 解析結果 fingerprint

したがって、時刻・施策・都市パッケージを変更した場合は、先に経路・KPI比較を再実行します。これは道路の色と表示中の経路/KPIが異なる条件になることを防ぐためです。

## 道路辺と品質状態

比較単位は道路ネットワークの `physicalEdge` です。CityGML/Runtime 解析の source edge が複数ある場合は、既存の経路比較と同じ加重集約済みコストを使います。

- `improved`（表示: 改善）: 指標が施策により改善した
- `degraded`（表示: 悪化）: 指標が悪化した
- `unchanged`（表示: 変化なし）: 許容差内で変化なし
- `partial`（表示: 一部欠測）: 施策前または施策後に一部サンプル未取得がある。残る有効サンプルで値を計算できるが、完全な比較ではない。
- `missing`（表示: 比較不能）: 施策前または施策後に有効サンプルがない。値を比較できない。

`partial` と `missing` は改善・悪化へ読み替えません。データ品質状態として確認します。

環境コストは既存の経路KPIと同じ式 `徒歩時間 + 日射曝露時間 × 日射回避係数` を道路辺単位へ適用します。係数とプロファイルIDはJSON証跡にも記録されます。

## 証跡出力

**道路別比較証跡（JSON）を出力**すると、`persistentDataPath/EnvironmentCostRoadHeatmaps/<areaId>/` に機械可読JSONを保存します。形式は [environment-cost-runtime-road-heatmap-comparison-0.1.schema.json](../schemas/environment-cost-runtime-road-heatmap-comparison-0.1.schema.json) です。

JSONには比較条件fingerprint、都市パッケージ識別子、基準/施策結果の provenance、全物理道路辺の値・差分・品質状態を含めます。PNGはRuntime Playerの画面解像度・カメラ状態に依存して証跡として再現性を担保できないため、このMVPでは出力しません。必要ならJSONを入力としてサーバ側または報告ツールで地図画像を生成します。
